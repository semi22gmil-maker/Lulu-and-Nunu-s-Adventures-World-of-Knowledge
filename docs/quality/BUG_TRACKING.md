# نظام تتبع الأخطاء والعيوب — BUG TRACKING

## 1. مستويات الخطورة (`Severity Levels`)
- **`P0 — Blocker (حرج مانع للإطلاق):`** انهيار التطبيق، فقدان بيانات الطفل من `IndexedDB`، تسرب بيانات خاصة، تجاوز بوابة الوالدين دون تحقق، أو فشل البناء `npm run build`.
- **`P1 — High (عالي):`** عطل في مسار أساسي (تعطل لعبة في عالم، عدم فتح مرحلة بعد إتمام السابقة، تداخل نصوص RTL يمنع النقر، تسرب ذاكرة WebGL).
- **`P2 — Medium (متوسط):`** خلل بصري غير معيق للوظيفة، تأخر عرض إطار أولي (مثل تحديث `CharacterCanvas` عند التبديل)، أو عدم تناسق معرفات بيانات ثانوية.
- **`P3 — Low (منخفض):`** تحسينات صياغة، تلميع رسومي، أو ملاحظات توثيقية.

---

## 2. آلية التسجيل في المستودع
- أي عيب مكتشف قبل أو أثناء مراجعة المرحلة يُسجل في [`../handover/KNOWN_ISSUES.md`](../handover/KNOWN_ISSUES.md) برقم معرّف ثابت (مثل `KI-001`) مع بيان الملف المتأثر، وخطوات إعادة الإنتاج، ووضع الإصلاح.
- عند العمل عبر GitHub Issues يُستخدم قالب [`.github/ISSUE_TEMPLATE/bug_report.md`](../../.github/ISSUE_TEMPLATE/bug_report.md).
- لا تُغلق أي مرحلة إذا كان بها أي عيب من الدرجة **`P0`** أو **`P1`** غير محلول.
