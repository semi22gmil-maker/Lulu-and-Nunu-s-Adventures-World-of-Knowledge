# معايير الاختبار — TESTING STANDARDS

## 1. مستويات الاختبار المطلوبة

| المستوى | الأداة | ما يجب فحصه | متى يعمل |
|---|---|---|---|
| **فحص الأنواع والبناء** | `npm run lint` (`tsc --noEmit`), `npm run build` | صحة TypeScript وعدم وجود واردات مكسورة | مع كل تعديل كود وفي CI |
| **اختبارات الوحدة والتكامل** | دوال القياس / Playwright / Node scripts | حراس `screenRouter`, محرك التكيف, مخازن `IndexedDB` | عند تعديل المنطق أو إضافة عالم جديد |
| **اختبارات E2E وWebGL** | Playwright (`chromium` + SwiftShader) | الحركات الـ 13، التعبيرات الـ 8، الشاشات الـ 14، القفل، الأوفلاين | عند إغلاق أي مرحلة وقبل الدمج |
| **الفحص البصري RTL واللمس** | Playwright Screenshots + فحص `boundingBox` و`scrollWidth` | عدم انكماش `<canvas>`، عدم القص في النصوص، أزرار `>= 44px` | في كل مرحلة واجهات أو عوالم |
| **اختبار الأجهزة الفعلية** | هاتف Android فعلي (المرحلة 16) | معدل FPS الحقيقي، الصوت `.ogg`، الحرارة، وزر الرجوع | قبل الإطلاق على Google Play |

---

## 2. شروط قبول أي اختبار E2E
- يجب تشغيل الاختبار ضد بناء الإنتاج (`npm run build && npm run preview`) وليس فقط خادم التطوير.
- يُحظر تماماً تزوير النتائج عبر `page.evaluate` لحقن بيانات غير ناتجة عن تفاعل حقيقي في اختبارات التدفق الأساسي.
- يجب أن يُسجل ملف `qa-results.json` أخطاء `consoleErrors`, `pageErrors`, و`failedRequests` وتكون جميعها مصفوفات فارغة `[]`.
